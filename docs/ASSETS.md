# Assets and visual references

[Documentation index](README.md) · [Rendering](RENDERING.md) · [UI framework](UI_FRAMEWORK.md)

World visuals are generated by shaders and simulation data; sound is synthesized
at runtime. The repository also carries authored text assets and licensed
binary UI fonts. Generated screenshots and experiment outputs are not runtime
art assets.

## Asset inventory

| Directory | Source and use |
|---|---|
| [assets/shaders](../assets/shaders/) | `.vert`/`.frag` world and GUI programs; loaded by shader managers |
| [assets/config](../assets/config/) | Six gameplay tuning files plus the separate UI theme |
| [assets/levels](../assets/levels/) | Authored JSON levels; only campaign-prefixed files appear on the campaign route |
| [assets/ui/icons](../assets/ui/icons/) | SVG cells, pathogens, abilities, resources, stat/control glyphs, mascot |
| [assets/ui/tree_layout.json](../assets/ui/tree_layout.json) | Generated tree coordinates/icons from the progression catalog |
| [assets/fonts](../assets/fonts/) | Static Fredoka 500/600/700 and Nunito 600/700/800/900 TTFs; OFL license |
| [docs/ui-concepts/canvas/project](ui-concepts/canvas/project/) | Committed HTML/index snapshot used for UI reference and icon extraction |

`assets/levels/*.json.bak` are backups, not discoverable `.json` levels.
The two `.webp` files in `docs` are existing reference images, not game runtime
textures. Root PNGs are local output ignored by Git; `scratch/` is also ignored.
Prefer writing new captures and temporary reports there.

## Runtime lookup

[platform/FileIO.cpp](../src/platform/FileIO.cpp) resolves an asset root once per
process. It first uses `IMMUNE_ASSET_ROOT` when nonempty, otherwise searches up
to eight ancestor directories from the executable for an `assets` directory,
then repeats from the current directory. `asset_path(relative)` appends
`assets/<relative>` to the discovered **repository root**.

```powershell
$env:IMMUNE_ASSET_ROOT = 'C:/path/to/horde'
```

Set this to the folder containing `assets`, not to `assets` itself. When using
out-of-tree build output, launching from the repository root is the usual
development workflow. A changed environment variable needs a new process
because lookup is cached. Explicit level/config paths remain their own inputs.

## Regeneration

| Command from repository root | Result and requirements |
|---|---|
| `python tools/build_fonts.py` | Downloads font sources/licenses and produces static TTF weights; needs fontTools and network |
| `python tools/build_fonts.py --src <folder>` | Uses local `<Family>-VF.ttf` sources; review the script's license handling for offline use |
| `python tools/extract_icons.py --check` | Compares generated icons with the committed canvas snapshot; standard library |
| `python tools/extract_icons.py` | Rewrites SVGs from that snapshot |
| `python tools/gen_tree_layout.py --check` | Checks layout against the live C++ catalog; standard library |
| `python tools/gen_tree_layout.py --preview scratch/tree.png` | Rewrites layout and renders a preview; Pillow required for preview |

Normal build/run needs the checked-in fonts, not fontTools. Keep
[OFL.txt](../assets/fonts/OFL.txt) with fonts when distributing them. The scripts
are authoritative for options and source URLs; see [Tools](TOOLS.md).

## Canvas workflow

[tools/ui_mockup](../tools/ui_mockup/README.md) contains HTML generators.
`hud_screens.py` writes Main, Placing, Inspect, Prep, Critical, and Kit;
`menu_screens.py` writes Menu, Tree, Levels, Victory, and Defeat. Both target
`tools/ui_mockup/project/`. Their `support.js` runtime comes from the external
design canvas and is not part of the game renderer.

The committed snapshot lives in `docs/ui-concepts/canvas/project/`, a different
directory from generator output. Icon extraction reads the committed snapshot,
so regenerating mockups alone does not refresh game icons. Review changes and
deliberately update the reference snapshot before extracting when appropriate.
Generated files are not all covered by the root ignore rules; keep temporary
mockups untracked or stage only the intended snapshot/assets.

The canvas preserves older stationary tower inspection/Sell and tree designs.
The current game deploys cells directly and uses a generated radial tree with
progressive reveal. Use runtime code and the maintained UI/gameplay docs for
interaction rules. The private external canvas is supplementary; local source
references are sufficient for maintenance.

## Changing appearance

For world art, edit the owning shader and its instance inputs; build success
does not validate shader behavior. Run the corresponding GL tests, inspect
shader logs, and capture close and wide views. For UI, update theme tokens,
widget code, or SVGs through their source workflow. Check pointer outlines
when shape geometry changes. Tune family/cell visual effects in their config
blocks and confirm they remain readable at horde scale.

See [Testing](TESTING.md) for captures and [Rendering](RENDERING.md) for shader
reload and visual effect contracts. Do not use an illustrative mockup's counts,
prices, or labels as a gameplay fixture.
