# UI mockup (Design canvas)

The source for the IMMUNE UI mockups on the Design canvas
<https://claude.ai/artifact/BmwSmwUEERL8X7rbVyfvWp> ("IMMUNE In-Match HUD", private to the owner's account).

The canvas holds one artboard per screen. Every artboard is generated by the two scripts here. Don't
hand-edit the `.dc.html` files. Change the scripts, regenerate, and republish.

| Script | Artboards |
|---|---|
| `hud_screens.py` | `Main`, `Placing`, `Inspect`, `Prep`, `Critical` (in-match HUD), `Kit`. Also holds the shared palette, cell-shaped panels, pathogen/tower/ability illustrations and the fake game world. |
| `menu_screens.py` | `Menu`, `Tree` (Strengthen Immunity), `Levels`, `Victory`, `Defeat`. Imports `hud_screens`. |

## Regenerate

```
cd tools/ui_mockup
python hud_screens.py
python menu_screens.py
```

Both write into `project/`. The generated `.dc.html` files are git-ignored. `project/canvas.json` (the
canvas index: artboard positions, titles and row notes) is tracked as a snapshot.

`menu_screens.py` reads live game data, so the mockups follow the code:

- `src/game/meta/ImmunityTree.cpp` supplies every skill-tree node's name, description, level count and cost weight.
  Costs follow `stat_base_cost` / `stat_cost_step` from `assets/config/meta.json`.
- `assets/levels/campaign_*.json` supplies level names and the mini-maps drawn inside each level-select stop.

## Publish

Ask Claude Code to publish the regenerated files to the canvas URL above, with `root` = `tools/ui_mockup`.
Send only the artboards that changed. Send `project/canvas.json` only when adding, moving, renaming or removing
an artboard, and first re-read the live index from the canvas, because it can be edited in the browser.

## Design decisions so far

- **Look:** the UI is built from the same biology as the game art. Every shape has the plum vessel outline.
  Immune (player-owned) panels are lavender cells; host panels are flesh. Pathogen yellow/green/brown is
  reserved for pathogens. Fonts: Fredoka for numbers and names, Nunito for text.
- **No faces** on cells. **No organ visual** anywhere yet.
- **Minimal text:** no flavour copy, no subtitles, no per-reward descriptions, no role lines on build cards.
- **In-match HUD:** organ integrity (colour only, no threshold marker), next-wave card, build tray, ability
  vesicles. No wave bar and no memory/antibody counters during a match (DESIGN.md §8).
- **Towers are placed inside the lane.** The buildable part of the lane is striped while placing.
- **Tower popup:** name, health and Sell only.
- **Skill tree:** a radial web on a large canvas you pan and zoom (drag, wheel, +/−, recenter, minimap). There
  are ten spokes: five towers, four abilities and the core upgrades. There are no literal web lines.
- **Level select:** pick a level on the route. Play appears once one is chosen. No preview panel.
- **Demo state** in the prototypes: levels 1–3 cleared and 4 open; 486 memory cells and 1 antibody; the
  starting tree levels are in `INIT_LV` in `menu_screens.py`.
